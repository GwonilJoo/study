### 이미 합의된 AWS 구성

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 리전 | 서울 (`ap-northeast-2`) | |
| 인스턴스 | **t3.medium** × 3 (2코어/4GB) | t2.micro(1GB)는 쿠버네티스가 안 뜬다 |
| 구성 | 컨트롤 플레인 1 + 워커 2 | 워커 2대여야 노드 장애 실습 가능 |
| OS | Ubuntu 24.04 LTS | 자료가 가장 많음 |
| 디스크 | 컨트롤 30GB / 워커 40GB, **gp3** | 기본 8GB는 부족 |
| VPC | **기본 VPC 사용** | 학습 단계에서 변수를 줄임 |
| 서브넷 | **3대 모두 같은 서브넷** | 문제 원인을 줄이려고 일부러 안 나눔 |
| 파드 CIDR | **192.168.0.0/16** (Calico 기본값) | AWS 기본 VPC가 172.31.x.x라 안 겹침 |

**보안 그룹** (가장 많이 막히는 지점)

| 유형 | 포트 | 소스 |
| --- | --- | --- |
| SSH | 22 | 내 IP |
| 모든 트래픽 | 전체 | **이 보안 그룹 자신의 ID** |

두 번째 규칙이 핵심이다. 소스에 IP가 아니라 보안 그룹 ID를 넣으면 "이 그룹을 붙인 서버들끼리 다 통한다"는 뜻이 된다.

### 비용에서 정확히 알아둘 것

**인스턴스를 중지하면 컴퓨트 요금은 멈추지만 EBS 디스크 요금은 계속 나간다.** 하루 2시간만 켜도 디스크 110GB는 24시간 과금된다. "생각보다 많이 나왔다"의 주범이 여기다.

> ⚠️ 확인 필요: 정확한 월 금액은 계산하지 않았다. **Day 15 시작 전에 AWS 요금 계산기로 확인한다.**

지금 확실한 것:

1. **예산 알림을 서버 만들기 전에 건다** (Billing → 예산)
2. 키 페어 `.pem`은 재발급 불가
3. 실습이 끝나면 인스턴스 중지, 완전히 끝나면 종료(Terminate)
4. 중지 후 재시작하면 **퍼블릭 IP가 바뀐다** (프라이빗 IP는 유지)

현재 사양(워커 4GB × 2)에서 프로메테우스(메모리 2~3GB)는 빡빡하다. **Grafana Alloy는 노드당 100~150MB**만 쓰고 저장은 외부에서 처리한다. Alloy는 저장소가 아니라 **수집기**이므로 보낼 곳이 따로 필요하다.

그 전에 **metrics-server**(100MB 미만)를 붙여 `kubectl top`부터 쓰는 것이 낫다.
