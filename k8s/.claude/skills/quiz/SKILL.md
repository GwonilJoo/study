# 복습 모드

사용자가 이전에 틀렸거나 검증하지 못한 것을 **다시 물어서** 확인한다.
설명하는 시간이 아니라 **사용자가 말하게 하는 시간**이다.

주제 인자: `$ARGUMENTS` (비어 있으면 전체에서 고른다)

## 1. 대상 모으기

아래 세 곳에서 **미체크 항목**을 모은다. 파일이 없으면 건너뛴다.

| 출처 | 찾을 것 |
| --- | --- |
| `logs/*.md` | 오답 노트의 `- [ ] 복습` |
| `README.md` | "검증하지 않은 채 남은 것", "복습 대기" 아래의 `- [ ]` |
| `docs/concepts/*.md` | `⚠️ 확인 필요:` 로 표시된 문장 |

```bash
grep -rn "^- \[ \]" logs/ README.md 2>/dev/null
grep -rn "확인 필요" docs/concepts/ 2>/dev/null
```

`$ARGUMENTS`가 있으면 그 주제와 관련된 것만 남긴다. 하나도 없으면 그 사실을 알리고, 전체에서 고를지 묻는다.

## 2. 한 번에 하나만 묻는다

- **항목을 목록으로 나열하지 않는다.** 몇 개가 남았는지만 알리고 바로 첫 질문으로 들어간다
- **정답이 적힌 노트 내용을 인용하지 않는다.** 질문에 답이 섞여 들어가면 복습이 아니다
- 원래 틀렸던 표현을 그대로 읽어주지 않는다. 그것도 힌트가 된다
- 질문은 **사용자가 설명하게 만드는 형태**로 낸다
  - 나쁨: "파드 IP는 언제 바뀌나요?" (단답)
  - 좋음: "파드를 재시작했는데 IP가 그대로였습니다. 왜 그럴까요?" (설명 유도)

## 3. 채점

| 판정 | 다음 행동 |
| --- | --- |
| 정답 | **"왜 그렇게 설계됐나"를 한 단계 더 묻는다.** 거기까지 답하면 통과 |
| 부분 정답 | 빠진 전제나 과잉 일반화를 **반례로** 짚는다. 정답을 덮어씌우지 않는다 |
| 오답 | 힌트 하나 → 그래도 막히면 부분 답 → 그래도 막히면 전체 설명 |
| "모르겠다" | 뜸들이지 말고 바로 설명한다 |

`⚠️ 확인 필요` 항목은 말로 채점할 수 없다. **클러스터에서 실측할 방법을 같이 설계하고 직접 돌린다.**
실측되면 노트의 `⚠️ 확인 필요:` 줄을 지우고 `## 근거`에 실측 결과를 추가한다.

## 4. 결과 반영

**통과했을 때만** 체크한다.

```markdown
- [x] 복습 (2026-09-07 통과)
```

통과하지 못하면 체크하지 않고, 해당 오답 노트의 **"왜 틀렸나"를 이번에 드러난 내용으로 보강**한다.
새로 드러난 오해가 있으면 현재 `logs/day-NN.md`의 오답 노트에 항목을 추가한다.

파일을 고친 뒤에는 **무엇을 어떻게 바꿨는지 한 줄로 보고**한다.

## 5. 마무리

한 항목이 끝나면 **다음 항목으로 갈지 사용자에게 묻는다.** 연달아 몰아치지 않는다.
세션을 끝낼 때 남은 미체크 개수를 알린다.
