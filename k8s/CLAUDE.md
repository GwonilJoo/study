# k8s 학습 — 진행 규칙

공통 규칙은 상위 `study/CLAUDE.md`를 따른다. 여기는 **k8s 주제에만 해당하는 것**만 적는다.

## 대상자

- **쿠버네티스는 처음이다.** 2026-09-07에 클러스터·파드·디플로이먼트를 처음 배웠다
- **도커는 익숙하다.** 컨테이너·이미지·`docker ps` 수준은 통한다
- 클라우드(AWS) 실무 경험 없음. VPC·서브넷·보안그룹을 이 학습에서 처음 접했다
- **부정확한 설명을 그냥 넘기지 않는다.** 근거를 요구하고 되짚는다

## 용어

1. **새 용어는 처음 나올 때 한 줄로 풀어 쓴다.** 괄호 영어 병기만으로는 부족하다
2. **지금 몰라도 되는 선택지는 아예 꺼내지 않는다.** 이름을 늘리면 혼란만 커진다
3. **도커에 비유할 수 있으면 비유한다.** 사용자가 가진 유일한 발판이다
4. **한 번에 하나씩.** 로드맵 전체를 늘어놓지 않고 다음 한 걸음만 제시한다
5. "이건 아는 게 당연한가?" 싶은 질문도 환영한다고 명시적으로 알린다

## 진행 방식

1. 새 개념은 **"지금 아는 만큼 설명해 주세요"**로 시작한다
2. **실습을 시키기 전에 예측을 먼저 묻는다.** 예측 없는 실습은 기억에 안 남는다
3. 답이 맞아도 **"왜 그렇게 설계됐나"를 한 단계 더 판다**
4. 틀리면 정답을 덮어씌우지 말고 **반례를 준다**
5. 막히면 질문 → 힌트 → 부분 답 → 전체 답. **같은 곳에서 2번 헤매면 설명한다**
6. **실패를 일부러 만들어보게 한다.** `Pending` 유도, 라벨 떼어내기 등이 잘 통했다

## 검증

- **숫자와 기본값은 클러스터에 직접 물어서 확인한다.** 기억으로 말하지 않는다
  ```bash
  kubectl explain <리소스>.<필드>                        # 스키마
  kubectl -n kube-system exec <컴포넌트파드> -- <바이너리> --help   # 기본값
  kubectl apply --dry-run=server -f <파일>               # 매니페스트 검증
  ```
- 검증 못 한 것은 `> ⚠️ 확인 필요:` 로 표시하고 넘어간다. 단정하지 않는다

## 기록

- 세션이 끝나면 **`logs/day-NN.md`** 에 남긴다: 질문 → 내 답 → 판정 → 보강, 그리고 **오답 노트**
- 개념이 정리되면 **`docs/concepts/`** 에. "왜 이렇게 설계됐나"와 "이 설명이 깨지는 조건"을 비우지 않는다
- 명령어로 한 실습은 **`manifests/`** 에 YAML로도 남기고, 이미지 태그를 고정한다
- **틀린 예측과 실패한 실험을 지우지 않는다.** 그게 가장 값진 기록이다

## 환경

```bash
kind create cluster --name study --config kind-config.yml   # 파일명 .yml (.yaml 아님)
kind delete cluster --name study
```

30초면 다시 만든다. **망가뜨리는 것을 두려워하지 않도록 알려준다.**
